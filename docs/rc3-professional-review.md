# RC-3 专业知识与康复安全审核

> 基线：`750cd3b`｜ 日期：2026-10-27
> 结论：**没有完成合格专业人员的独立审核。高风险康复/伤病内容、医学营养场景与疼痛相关教学不得宣称“已获专业认可”。RC-3 门槛未通过。**

## 0. 审核状态定义（可追溯）

| 状态 | 含义 | 必须记录 | 不能做什么 |
|---|---|---|---|
| **已审核** | 指定领域的合格专业人员对**该版本内容**逐条/逐卡审核通过，且记录审核范围、证据、日期、版本/指纹 | 审核人姓名/资质、机构/利益冲突声明、审核日期、内容版本或指纹、审核意见、适用范围 | 不能把“产品负责人签核”“内部校验”“AI 整理”写成专业审核 |
| **待审核** | 内容已存在，但没有合格专业人员对当前版本完成审核 | 待审原因、风险级别、临时门（不展示/不用于处方/只作一般信息） | 不能作为处方、诊断、康复计划或“专业认可”宣传 |
| **审核不通过** | 专业审核发现错误、越界、证据不足或适用条件不成立 | 不通过原因、影响范围、下线/修订记录 | 不能继续以原版本服务 |
| **不适用于当前用户** | 内容本身可能已审核，但与当前用户的条件/目标/限制不匹配 | 用户条件、排除理由、复核时点 | 不能把“不适用”当成“内容错误”或“已审核” |

四个状态是**内容版本 + 用户条件**的独立维度：一张卡可以“已审核但对当前用户不适用”；也可以是“待审核且当前用户可用（仅一般信息）”。当前系统只有部分状态字段，尚未把四态完整落到 UI/审计表。

### 1.1 关于 60 张教练卡

60 张卡有完整的签核指纹与版本记录，这是**内容治理**的正面证据：改动正文/limits/绑定/用途会使旧签核失效。但审核人是发起人（产品负责人），不是运动医学、物理治疗或注册营养师；卡片来源主要是三位博主的公开分享转述。它们可以作为“个人使用的教学整理”，不能在发布材料中写成“经专业审核”。

其中 **39 张卡**在正文/limits 中出现疼痛、伤病、康复、弹响、不适等词（例如 `card-action-lateral_raise`、`card-action-dips`、`card-action-knee_push_up`、`card-action-leg_press`、`card-action-lying_leg_curl`、`card-action-reverse_back_extension`）。这些不是“错误”，但属于 RC-3 的高风险抽样对象：需要专业人员确认疼痛前提下的幅度/替代/停止条件，以及是否应改为“仅一般信息”。

### 1.2 关于分流规则

`triage_rules.py` 的分流是**信息分流**，不是诊断；规则明确写了“未报告危险症状 ≠ 没有危险症状”。但红旗词表、持续 14 天阈值、日常功能受限阈值、区域映射与限制建议均为系统默认，未经急诊/骨科/运动医学/物理治疗专业审核。以下内容属于高风险，必须由相应专业人员复核：

- 心血管红旗（胸闷/胸痛/气短/晕厥/心悸）与“立即就医”话术；
- 创伤后无法负重、进行性肿胀、夜间静息痛的紧急度；
- 麻木/放射/无力/交锁/打软腿的转诊边界；
- `triage_recommended` 限制的“只收紧不放松”、复核时点与解除纪律；
- `professional` 限制的解除仅凭用户录入专业说明（≥10 字）是否足够；
- 疼痛区域 → 动作限制的区域/关节映射是否过宽或过窄。

### 1.3 关于营养

营养模块没有医学营养治疗（MNT）资质，也没有孕期/糖尿病/肾病/进食障碍等场景的确定性阻断。当前只靠专家提示词中的“不提供医学饮食治疗建议”。这不足以支撑“专业安全”：

- 孕期能量限制、糖尿病碳水循环、用药与补剂相互作用、严重过敏原替换，均需要医生/注册营养师；
- 食物库 NULL 值已正确表示“未知”，但“未知”不应被模型补成 0 或经验值；
- 过敏原信息目前依赖用户档案，缺少交叉污染/隐藏成分的审核。

## 3. 审核方法与记录模板（待执行）

### 3.1 审核人资格

- 运动科学/训练：运动科学硕士以上或有认证力量教练（CSCS 等）+ 至少 3 年带训经验；
- 营养：注册营养师（RD/中国注册营养师）或有临床营养经验；
- 康复/伤病：骨科/运动医学医生或物理治疗师（PT）；
- 动作教学：具备相应动作教学资质与至少 3 年教学经验；
- 每位审核人需声明利益冲突（是否与博主/品牌/补剂有商业关系）。

### 3.2 每条内容的审核记录

```json
{
  "content_id": "card-action-lateral_raise",
  "content_version": "v1",
  "content_fingerprint": "…",
  "domain": "movement/rehab",
  "reviewer": {"name": "…", "credential": "…", "conflict": "none"},
  "reviewed_at": "YYYY-MM-DD",
  "status": "approved | pending | rejected | not_applicable",
  "scope": "适用人群/动作/疼痛前提",
  "findings": ["…"],
  "required_changes": ["…"],
  "evidence_refs": ["…"],
  "next_review_at": "YYYY-MM-DD"
}
```

### 3.3 审核问题清单（节选）

- 该建议是否把“一般信息”写成了“诊断/治疗/处方”？
- 是否明确了停止条件、红旗与转诊路径？
- 是否把博主个人经验当成普遍证据？是否标注来源与局限？
- 疼痛/伤病前提下的幅度、替代、复训是否保守？
- 营养建议是否涉及医学营养治疗、孕期、用药、过敏？是否应转介？
- 视频观察是否越界为动作正确性评分/伤病归因？
- 是否对“当前用户”的条件（伤病、限制、孕期、用药）做了适用性判断？
- 文案是否出现“专业认可/临床验证/保证效果”等不能证明的表述？

## 4. 当前结论与发布影响

- **已审核（合格专业人员）**：0 个内容面完成。产品负责人签核、内部 YAML 校验、AI 整理均不计入。
- **待审核**：上表全部内容面；高风险项 RC3-H1–H8 优先。
- **审核不通过**：本轮没有外部专业审核，故没有“审核不通过”记录；这不代表内容已被证明正确。
- **不适用于当前用户**：系统有用户条件/限制，但尚未形成逐内容的适用性记录；不能把“用户没报告”当成“适用”。

**RC-3 = NOT PASSED。** 在完成至少康复/运动医学与营养两个领域的独立专业审核前：

1. 不得在 README、P10、发布页或应用内写“专业审核/专业认可/临床安全”；
2. 高风险康复指导应保持“待专业审核”标注，必要时只展示“停止并就医”而不给训练建议；
3. 孕期/糖尿病/用药等医学营养场景应转介，不生成个体化处方；
4. 39 张涉及疼痛/伤病的卡片应抽样专业审核，未审核前按“个人教学整理”定位。

## 5. 与 RC-1/RC-4 的关系

- RC-1 的模型安全评测只能证明“模型在这些样本上没有严重安全错误”，**不能替代**专业内容审核；零次严重错误不等于临床安全。
- RC-4 的真实用户试用不能替代专业审核；用户“没出事”不是有效性/安全性证据。
- 专业审核完成前，RC-5 只能是 `BLOCKED` 或明确限制功能范围的 `CONDITIONAL`；本任务书的结论见 [rc-release-decision.md](rc-release-decision.md)。
