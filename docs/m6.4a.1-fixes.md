# M6.4-A.1 — 数据与会话一致性收尾

日期：2026-10-25 · 前置：M6.4-A（`455cfde`）复查通过（功能验收通过，三项 P0 集成收尾）。

## 一、P0-3：统一分型指标服务

新增 `coach/analytics/exercise_metrics.py` 顶层函数，**全站唯一公式来源**：

- `set_volume(log)`：weight_reps=负重×次数；bodyweight_reps=**额外负重**×次数
  （自重不可比不计入）；assisted/duration/distance_time 不产生 kg 容量。
- `set_e1rm(log)`：仅 weight_reps 在 1-12 次区间计算；其余类型返回 None。
- `entry_set_type(logs)`：一条动作记录的类型判定。

接入点：动作详情 `exercise_sessions`（原来就地实现）、日历/周期汇总（原来
`weight_kg×reps` 硬编码）、`db._recompute_exercise_states`（派生状态此前会对
bodyweight_reps 的聚合"额外负重 5kg"套 Epley 算出 ≈6.3kg 的伪 e1RM——现在
非 weight_reps 口径不参与）。

**一致性回归**（`test_volume_consistent_across_views_and_typed_recompute`）：
同一组负重引体（5kg×8）+ 卧推（60×10）数据 → 动作统计容量 40、日历与周期
容量 640（600+40）、派生状态 `best_e1rm=None`、`last_weight=5`。

## 二、P0-1：历史纠错分型适配

- `lib/checkin.ts`：`SetEdit` 扩展为分型字段（added/assist/minutes/seconds/distance）；
  `initSetEdit()` 从原记录初始化编辑值；`buildCorrectedData()` 按类型只覆盖
  用户改动的字段——**type/at/warmup/未触碰字段永远原样保留**；
  `deriveAggregates` 分型取负荷（bodyweight_reps=额外负重，与后端 `_load` 同口径）；
  raw 重建改用 `formatSetCompact` 分型文案。
- 纠错弹窗按类型渲染输入行（重量×次数 / 次数+额外负重 / 次数+辅助 / 分秒 /
  距离+分秒），校验与训练执行**共用 `validateSetDraft`**——复查要求"两处不漂移"。
- 端到端：混合记录（卧推+引体+平板）纠错——引体额外负重 5→7.5、平板 1:30→2:00，
  保存后落库核验：两组类型/时间戳/未触碰组完整保留，修订 v0→1。

## 三、P0-2：模板会话身份

- `WorkoutSession` 增加 `templateId / planId / planVersion`；
  `startFreeSession({label, templateId})` 以 templateId 为会话身份：
  同模板（含同为纯自由）→ resumed 恢复；不同模板 → 走保留/放弃弹层；
  无进度时允许直接切换。计划会话携带 plan 元数据，保存时写入 `session_meta`
  （template_id / plan_id / plan_version）——训练来源可追溯，为 M6.5 准备。
- 端到端：模板 2 会话（1 组记录）→ 进入模板 1 → 弹出「模板 · 胸背超级组日
  （已记录 1 组）」保留提示 → 回到进行中的训练后 `templateId=2`、记录完整。

## 四、P1：后端分型必填字段校验

`coerce_checkin` 按类型校验本质量字段，缺者**整组剔除并说明**（不再"丢字段
后入库"）：duration 缺时长、distance_time 缺距离/用时、assisted_reps 缺辅助
重量、weight_reps/bodyweight_reps 缺次数。覆盖离线恢复/API/导入等所有入口。
测试：三种缺失各出警告并剔除，合法组保留。
