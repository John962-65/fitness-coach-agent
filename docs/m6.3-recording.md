# M6.3 — 专业训练记录与数据分析

日期：2026-10-25 · 前置：M6.2 第一阶段（`d72bc37`）。
本阶段目标来自训记对标复查：**让 Fitness Coach 即使不用 AI，也是一款愿意每天打开的专业训练记录应用**。

## 一、自由训练模式（P0）

- `store.ts`：训练会话升级为带身份的对象——`id`（稳定会话 ID）+ `mode: 'planned' | 'free'`；
  旧持久化会话自动补默认值（升级不丢进行中训练）。
- 路由 `/workout/free`（复用沉浸式布局）：进入即建空会话，**添加动作 → 逐组记录 → 随时增删动作 → 完成保存**，
  全程不依赖计划、不影响当前计划。选择器选择动作时携带稳定 `exercise_id`。
- 入口：今日页（主视觉卡下方）与训练页（训练日切换行尾）均有"自由训练"。
- 防误伤：若已有进行中的计划训练且已记录组数，进入自由模式会被拦截提示先完成。
- 保存：raw 前缀为「自由训练 日期」，服务端按普通训练记录入库。

## 二、训练记录身份完善（P0）

- 保存时随记录提交 `exercise_id`（临时替换提交替换后的 ID）。
- 后端：`save_checkin` 只在客户端提供的 id **确实存在**（内置库或本人自定义）时采信；
  否则回退为原有的名称系统判定（含别名归一与未识别动作队列）。防止伪造 ID 污染统计。
- 效果：自定义动作、临时替换、同名变式的长期统计有了稳定锚点（`test_checkin_preserves_valid_exercise_id`）。

## 三、逐组口径的分析模块（P0）

新增 `coach/analytics/`（不再把分析逻辑堆进 review.py）：

- `exercise_metrics.py`：动作历史会话（新→旧）——工作组数、总次数、
  **容量 = Σ 组外部负重×次数**（自重组贡献 0，如实呈现）、最佳组、
  **e1RM 逐组计算取最佳（仅 1-12 次区间，Epley）**、会话时长（由逐组完成时间推算）；
  `personal_records()`：最大重量 / 最佳估算 1RM / 最多次数 / 单次最大容量 四类 PR。
- `training_calendar.py`：月历聚合（每天训练次数/工作组数/容量，**同日多次合并计数**）；
  周期汇总（训练次数、训练天数、频次/周、工作组数、容量、**肌群分布按 primary 主肌群归口——一组只记一次不重复统计**、平均时长）。
- 新端点：`GET /users/{uid}/exercise-stats/{exercise_id}`、`/training-calendar?year&month`、`/period-summary?days`。
- 复查指出的口径问题已修正：统计全部直接基于 `set_logs`，不再混用"容量最大代表组"。
- 兼容性回归：浏览器 `toISOString()` 的 `Z` 后缀时间戳解析（曾导致 500，已修并有测试）。

## 四、前端

- **动作详情新增「我的表现」标签**（第四标签）：PR 四宫格（含日期与 e1RM 口径说明）、
  力量趋势 SVG 折线（无图表库依赖，`components/charts.tsx`）、
  逐会话历史表（日期/最佳组/组数/容量/时长，可展开看每一组）。
  无记录时如实显示空状态。
- **训练历史重构**：`记录列表 | 日历与统计` 双视图。
  日历视图 = 月历（周一起始、绿色标记训练日、×n 同日多次、点击看当天完整记录）
  + 周期统计（7/30/90 天切换：次数、工作组数、容量、平均时长、肌群分布条形图）。
  列表视图 = 类型筛选 + 关键字搜索（数据窗口提升至 50 条，后端 limit 上限同步放宽）。
- 今日页 / 训练页的自由训练入口。

## 六、边界说明

- **容量与 e1RM 都是模型/口径指标**：容量不等于肌肉刺激；e1RM 是估计值（UI 已标注"不等于实测极限"）。
- 训练时长由逐组完成时间推算（首末差），休息跳过/暂停会被低估——后续会话内计时器可补。
- 肌群分布仅按 primary 主肌群归口（复查建议的防重复统计口径），协同肌群参与度未体现。
- 本阶段未做：训练模板库、多记录类型（时长/距离/辅助负重）、超级组、三维演示、AI 读统计——
  分别属 M6.4 / M6.5，遵循复查的路线排序未提前摊开。
