## 一、M6.5-0 统一训练事实服务

**`coach/analytics/fact_service.py`**：`get_training_facts(db, user_id,
window_days, exercise_ids=None)` 输出结构化事实（非拼好的文本），每条含
`fact_id / metric / value / unit / measurement_type / window / source_ids /
calculation / data_quality / status(observed|estimated|insufficient)`。

十项要求落点：

| 要求 | 实现 |
|---|---|
| 复用现有逐组指标 | 只调 `exercise_metrics` / `period_summary`，零新公式 |
| 分型区分 | 实际记录类型优先（辅助/时长按记录口径），库声明兜底；`MEASUREMENT_METRICS` 声明各类型主进步指标 |
| 自由/计划/模板 | 会话身份读 `session_meta`（mode/plan_id/template_id） |
| 稳定 ID + 本地日期 | `entry_identity` + `session_local_date` |
| 排除热身组 | `_working_sets`（复用） |
| 尊重纠错后版本 | 读 checkins 当前行；`source_ids=checkin:{id}:revision:{n}` 保留追溯 |
| 数据不足 | `status=insufficient, value=None`，绝不用 0 冒充 |
| 任意时间窗 | SQL `since` 过滤 + 本地日期精确过滤（非"最近 N 条"） |
| 客观/估算/主观区分 | observed / estimated（e1RM 注明 Epley）/ RPE 标注"用户主观自报" |
| 计划完成率 | 仅 `mode=planned 且 plan_id=当前生效计划` 计入；(day, 本地日期) 去重；自由/模板不计入并在 data_quality 说明 |

**验收（三接口一致）**：`test_m65_scenarios.py::
test_three_interfaces_consistent_over_http` 用同一份种子数据断言
「我的表现」(`/exercise-stats`)、「周期统计」(`/period-summary`)、
AI 训练事实（fact_service）的数值/单位/口径一致——一致由**同源构造**保证。

## 二、M6.5-1 事实接入 AI 教练

新增**只读工具**（`coach/agent.py`，按需获取，不整段注入历史）：
`get_training_facts` / `get_exercise_progress`（含序列+趋势）/
`get_training_history`（会话摘要）/ `get_trial_evidence`（尝试证据）。

系统提示新增规则 7a（数据纪律）：先取数再回答；引用数值必须来自工具返回；
区分用户原话/记录/计算/估算/知识/推断；无记录不编造；非负重-次数类不引
e1RM；用户不想改不硬找改动点。

## 三、M6.5-2 可解释趋势分析

**`coach/analytics/progress_analysis.py`**：`analyze_progress(series,
measurement_type)` → `improving / stable / declining / insufficient` +
证据（前后半窗中位数/样本/跨度/相对变化）+ 限制（缺口/口径）。

可比性纪律：指标按测量类型选择（e1RM 只属 weight_reps 1-12 次；自重看
次数/额外负重；辅助看辅助重量；时长/距离各归各类）；样本 <3 次、跨度
<7 天、半窗缺口 >21 天 → insufficient；±2.5%（负重类）/±2 次（次数类）
为方向阈值；措辞约束："短期波动不等于平台期，趋势不直接归因于方案"。

## 四、M6.5-3 多方案建议与用户自主决策

## 五、M6.5-4 个人尝试与复盘

复用 PersonalTrial，不建第二套对象。新增 `coach/analytics/
trial_evidence.py`：

- `snapshot_baseline`：开始尝试时自动固定基线（关键事实快照，随 trial 落库）；
- `trial_evidence`：尝试期间事实 + 趋势 + 执行情况（计划完成率/训练缺口）；
- `review_draft`：复盘草稿三节——**已观察结果 / 可能解释 / 无法确认的
  原因**；执行不完全时明确"归因不可靠"；结论仅适用于本人。
- 新工具 `review_personal_trial` 生成草稿；决策 keep/adjust/stop 仍由用户
  表态后走既有 `end_personal_trial`（`test_scenario_c_trial_lifecycle`
  全链路覆盖）。

## 八、已知限制

1. FAKE LLM 模式下的对话演示只验证**管道**（取数→引用→可追溯），
   真实模型的建议质量需按评测报告的"待人工项"抽样复核。
2. 趋势阈值为教学常识级默认值（±2.5%/±2 次），未做个体化校准；
   结论措辞已限制为四态，不输出平台期断言。
3. 计划完成率的"应练次数"按每周计划日数×窗口周数推算（estimated），
   未考虑计划中途变更的分段（按当前生效计划计）。
4. RPE 类事实是用户主观自报的汇总，仅描述不推断。
5. 复盘草稿的"可能解释"由规则模板生成（趋势+混杂因素提示），不做因果
   归因——这正是设计边界。
