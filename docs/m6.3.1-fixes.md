# M6.3.1 — 集成收尾：会话边界、自定义动作统计贯通、按日期查询

日期：2026-10-25 · 前置：M6.3（`5e06618`）复查通过（核心验收通过，边界项待收尾）。
本阶段为复查建议的"一次小范围修复"，不新增功能面。

## 一、P0-1：会话切换保护下沉 store

- **问题**：自由训练有已记录组时，从任意入口启动计划训练会静默覆盖原会话（反向此前已有保护，但只在页面入口检查）。
- **修复**：保护逻辑下沉 `store.ts`——`startSession` / `startFreeSession` 在已有含记录的会话且目标不同时
  返回 `{ kept: true }` 并**保留现有会话**，不创建新会话；所有入口（今日/训练/历史恢复等）统一受保护。
- **交互**：Workout 检测到 `kept` 后弹出明确选择 Sheet：
  「回到进行中的训练」（跳转恢复）/「放弃已记录的组，开始新的」（用户显式放弃后才清空重建）。
  关闭弹层等同恢复现有会话。**任何路径都不再静默覆盖。**
- 实测：自由训练记 2 组 → 转计划训练 → 弹层出现（"自由训练（已记录 2 组）"）→
  「回到」后两组完整保留；「放弃并开始新的」后计划会话正常创建（截图 `m631-switch-prompt-390.png`、`m631-kept-free-390.png`、`m631-discard-start-390.png`）。

## 二、P0-2：自定义动作统计贯通

统一身份解析（ID 优先、名称/别名回退，**内置 + 本人自定义同口径**，与 `exercise_service.get_exercise` 一致）：

- `exercise_metrics`：`entry_identity()` 替代内置库绑定的 `_same_exercise` 匹配；
  `exercise_sessions` 对自定义动作完整可用（此前会返回空）。
- `training_calendar`：肌群归口按用户可见动作文档解析——自定义动作使用其自身 `primary`，
  不再落入 `other`。
- `db.record_checkin` / `revise_checkin` / `_recompute_exercise_states`：
  派生状态（user_exercise 的 last_weight/e1RM）同样覆盖自定义动作（此前被内置库过滤静默跳过）。
- **端到端测试**（`test_custom_exercise_end_to_end`）：创建 → 携带稳定 ID 训练 → 历史与 PR →
  肌群归口（chest 而非 other）→ 派生状态 → 旧记录（无 ID）按别名回退解析，共 8 项断言。

## 三、P1：按日期查询训练记录

- `GET /users/{uid}/checkins` 新增 `date=YYYY-MM-DD`（非法格式 422）与 `offset` 分页；
  `db.list_checkins` 同步扩展。
- 训练日历"点击某天"改为按日期向服务端查询当日完整记录——**不再受最近 50 条列表窗口限制**，
  与日历聚合口径一致（骨架屏加载中）。

## 四、会话元数据与本地日期（M6.4 前置）

- 保存训练时随记录入库 `session_meta`：
  `{session_id, mode, started_at, completed_at, local_date, timezone}`（顶层字段透传，兼容旧记录）。
- **用途**：自由/计划执行比例、真实训练时长（含休息）、跨时区口径的统计基础。
- 分析侧已接入：会话时长优先 `completed_at - started_at`（旧记录回退逐组时间跨度）；
  **训练所属日期优先 `local_date`（用户本地日期），旧记录回退服务器时间**——
  `store.ts` 的会话日期同步改为本地日期（原 UTC ISO 在临近午夜不是用户所在日期）。
- 回归测试：日历按 `local_date` 入格、时长优先真实起止（`test_session_meta_local_date_and_duration`）。
