### P1-1 播放器循环切换状态不同步（已修复 + 浏览器回归）

问题：`AnimatedModel` 的初始化 effect 依赖含 `loop`，切循环会重建
AnimationAction → 时间归零且暂停，父组件 `playing` 状态不同步。

修复：Action 生命周期只由 [scene, mixer, animationName] 决定；`loop` 单独
effect 仅调用 `action.setLoop()`，保留时间/速度/暂停态；新增 mixer
`finished` 事件 → 父组件同步按钮回"播放"；单次模式停在末帧后再点播放会
回到开头。浏览器回归（审查指定场景）实测：播放 1.5s → 切循环 → 继续播放
→ 暂停 → 切回循环 → 恢复播放，时间轴 1.5→1.6→2.2→2.2→2.2→2.7s 全程
不归零、按钮状态一致。

### P1-2 动作质量门控（新增 `tools/exercise3d/quality.py`）

导出前强制通过（违反即中止构建）：

| 检查 | 口径 |
|---|---|
| 关节连续性 | 相邻关键帧骨骼旋转 ≤30°；首尾衔接 ≤15°（循环平滑） |
| 关节活动范围 | 膝屈曲 ≤150°、髋矢状面角 ≤140°（**按动作声明覆盖**：硬拉 155°、划船 150°——铰链类天然更深） |
| 器械-头部间隙 | 杠铃杆/哑铃与头部球最小间隙 ≥ −5mm |
| 器械-地面 | 杠铃片底缘 ≥ 地面 −4mm（允许恰好触地） |
| 足底接触 | 双脚世界旋转偏离单位阵 ≤2.5°（脚掌平贴不侧翻） |
| 双侧对称 | 腿旋转镜像差 ≤8°；肘世界坐标镜像偏差 ≤12mm |

**门控立即抓到两个真实问题并已修复**：

1. 躯干前倾分配 bug：三个躯干骨骼给的是世界目标旋转，0.30/0.35/0.35 的
   "分配"实际不累加（胸部世界俯仰只有 0.35×lean）。深蹲视觉上侥幸可看、
   硬拉起始位因此塌陷。已改为世界目标 0.30/0.65/1.00（局部累加恢复设计
   意图），深蹲底部上背自然前倾 20-30°（截图复核）。
2. 硬拉起始位膝屈曲 158°（近乎深蹲）。经参数扫描修正为铰链式起始
   （背角约 22° 高于水平、膝屈曲 124°、臀高于膝、杠片触地），截图复核通过。

质量门控是**离线几何合理性**门槛，不等于专业动作学认可（见 §六-4）。

## 三、B2/B3：三维动作演示引擎

### 制作方式（重要偏离说明）

**Blender 在本环境不可用**（无法产出 .blend 工程文件）。等价方案：
`tools/exercise3d/` 程序化生成包 —— 该包即「可编辑工程源文件」（改动
骨骼/动画 = 改 rig.py / motions/*.py 后重导出）：

```
tools/exercise3d/
├── rig.py          # 26 骨骼真实层级（Mixamo 风格命名）+ FK + 2 连杆 IK
├── meshgen.py      # 蒙皮人体网格（关节融合顶点权重，真实 skinning）
├── equipment.py    # 杠铃/哑铃/平凳/立式靠背凳/地面
├── gltfbuild.py    # 手写 GLB 序列化（skin/动画通道/材质）
├── motions/        # 五个动作的运动学脚本（公共求解器 common.py）
├── build.py        # python3 -m tools.exercise3d.build <id...>
└── manifest.py     # manifest 生成/更新（sha256、阶段表、预览图）
```

- 空间规范：Y-up、米制、角色面朝 +Z、地面 y=0、杠铃沿 X；人台身高 1.78m。
- **动画是真实骨骼驱动**：关键帧覆盖髋/膝/踝(足)/躯干/肩肘手 + 器械平移，
  局部旋转由「目标世界姿态」烘焙；顶点带蒙皮权重（关节区 50/50 融合带），
  绝非整体平移冒充。
- **人-械同步由构造保证**：器械握点由同一套运动学解算（杠位=双肩中点+胸廓
  系偏移；卧推/硬拉/划船/肩推的器械路径锚定 FK 实测肩位），生成期自检
  脚踝漂移/握点间隙 < 1e-15（`motions.*.build()['checks']`）。
- 深蹲杠轨迹钉在脚中正上方（z=0.05±1e-15，两遍解算）。
