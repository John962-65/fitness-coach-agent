# M6.1 — 训练交互完善与真实用户试用准备

日期：2026-10-25 · 前置：UI/UX 全面改版（`b38c7a2`，见 `docs/ui-redesign-v2.md`）
本轮目标来自复查意见：**先修重要交互问题，再补真实场景验收**。视觉框架不再推翻。

## 一、P0 修复：历史纠错不再丢失逐组记录

**问题**：旧纠错弹窗把训练记录压缩成"每动作一条聚合值"提交，`set_logs` 被整体丢弃——用户纠正一组，整条训练的逐组数据（含热身标记、完成时间）都被覆盖。

**修复**（纯前端，后端协议零改动）：

- 新增 `frontend/src/lib/checkin.ts`：`buildCorrectedData()` 从原记录出发构建完整纠错载荷——
  - 逐组动作：每组只覆盖与原值不同的 weight/reps/rpe；`warmup` 与 `at` 永远原样保留；
  - 聚合字段（sets/weight_kg/reps/rpe）按后端 `save_checkin` 的同一规则重建（代表组=正式组中容量最大者，并列取重量更大、先出现者）；
  - 训练 `raw` 按纠正后的正式组重写，保留原"日期前缀"与"备注"段；
  - `raw` 之外的未知字段、`exercise_id` 原样保留；非法数字输入返回 null 拦截提交。
- `History.tsx` 纠错弹窗重写为**逐组编辑**：每行 = 组号 + 热身标签（只读）+ 重量/次数/RPE；无 `set_logs` 的旧聚合记录沿用整动作编辑。
- 锁定测试 `src/lib/checkin.test.ts`（11 个用例：聚合规则、只改一处、时间戳保留、显式清空、非法输入拦截、未知字段保留、旧记录兼容、raw 重建）。

**端到端实测**：对含 2 组深蹲的记录只把第二组 80→85 提交，落库结果 `revision 0→1`，第一组 80×10 原样、第二组 85×10，两组 `at`/`warmup` 完整（截图 `m61-history-correct-perset-390.png`）。

## 二、训练执行输入校验与快捷步进

`Workout.tsx` SetForm：

- **正式组次数必填**（≥1）才能完成；重量可留空（自重动作）；RPE 可选但限 1-10；
- 所有输入做数字合法性校验（此前非数字会被 `JSON.stringify` 静默变成 null 落库）；
- 新增常驻快捷步进行：**重量 −2.5/+2.5 kg、次数 −1/+1**（空值时负向禁用），免键盘连续记录；
- 错误以行内红字提示，输入即清除（截图 `m61-workout-validation-390.png`、`m61-workout-steppers-390.png`）。

## 三、动作封面请求性能

`components/media.tsx`：

- **IntersectionObserver 懒加载**：卡片进入视口（含 200px 预载边距）才请求该动作的媒体列表；
- **模块级缓存**：同一动作全站只查一次（上限 400 条 LRU），重复渲染/回访零请求。

**实测**（70 个动作的探索页）：首屏仅 7 次请求（旧实现 70 次），滚动两屏后累计 29 次，按需递增。

## 四、内部数据不再直接暴露

- `Mine.tsx` 摘要文本经 `humanize()` 转换：`muscle_gain→增肌`、`intermediate→进阶`、`gym→健身房` 等（截图 `m61-mine-humanized-390.png`）；
- `MineApproach.tsx` 强度风格显示中文标签（`periodized→周期化`）；
- `ExploreDetail.tsx` 区分两种状态：**结构化资料已审核** ≠ **教学内容已完善**——教学标签为空时明确说明"图文教学要点尚未录入"并引导用「动作分析」/「知识依据」（截图 `m61-detail-teaching-copy-390.png`）。

## 五、真实 AI 对话验收（本轮最关键的补充验证）
