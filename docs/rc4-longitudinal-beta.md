# RC-4 长期真实使用验证（T6）

> 基线：`750cd3b`｜ 日期：2026-10-27
> 结论：**T6 未执行。没有招募受试者、没有知情同意、没有 2–4 周真实使用数据；本文只给出可执行的试用方案与验收口径。RC-4 门槛未通过。**

## 0. 为什么不能“本轮完成”

T6 的定义是**知情、自愿的小规模受控试用，观察 2–4 周**。它依赖真实用户、真实训练/饮食/恢复记录与时间跨度；不能用：

- 自动化测试替代（只能证明代码路径，不证明真实使用）；
- FAKE LLM 或单人一次性点测替代（不能观察长期记录、提醒疲劳、缓存膨胀）；
- 真实模型评测替代（T4 只看模型输出，不看用户理解与负担）；
- 现有 E2E 截图替代（桌面移动视口、合成数据、单次会话）。

因此本轮不填写任何受试者数据，也不把 P10 的“开发侧就绪”写成“长期可用”。

## 1. 试用设计（待执行）

### 1.1 目的

回答任务书五个问题：

1. **记录是否可靠？** 数据丢失、重复保存、日期错位、统计不一致；
2. **AI 是否真正有帮助？** 能否理解推荐依据、是否出现无关建议/过度提醒；
3. **跨专家是否发挥价值？** 多观点是否帮助理解选择，而不是增加决策负担；
4. **PersonalTrial 是否可用？** 能否从一次建议出发持续记录、复盘并自主决定保留/改变；
5. **移动端是否方便？** 真实训练时能否快速记录、点击是否过多；
6. **系统能否长期恢复？** 缓存异常、数据膨胀、历史不可读。

### 1.2 受试者

- 规模：建议 5–10 名，至少 3 名完成 4 周；单平台用户需标注平台。
- 纳入：18 岁以上；有规律训练（每周 ≥2 次）或明确开始计划；能使用自己的手机；愿意记录训练/饮食/恢复。
- 排除：孕期、未稳定的伤病/急性症状、医生限制训练、正在接受医学营养治疗、无法理解知情同意者；这类用户需要专业路径，不进入通用试用。
- 招募：知情自愿，不招募项目成员本人；避免利益冲突；不支付与“好评”挂钩的报酬。

### 1.3 知情同意（必须包含）

- 试用目的、时长、需要记录的数据（训练/饮食/恢复/身体/症状/视频可选）；
- 数据用途：仅用于本次产品评估；**不用于模型训练**；不公开个人身份；
- 风险：不是医疗建议；出现红旗症状应停止并就医；AI 可能出错；
- 权利：随时退出、要求删除数据、拒绝上传视频/敏感信息；
- 存储：本地/受控服务器位置、访问者、保留期限（建议试用结束后 30 天内删除或匿名化）；
- 联系人/投诉渠道；同意书版本与签署日期。

### 1.4 时间线

| 阶段 | 时间 | 动作 |
|---|---|---|
| 筛选与同意 | Day -3–0 | 资格问卷、知情同意、设备/浏览器记录、基线问卷 |
| 入门 | Day 1 | 建档、计划、演示记录/复盘/导出；不替用户做决定 |
| 第 1 周 | Day 1–7 | 每日训练/饮食/恢复记录；每周短问卷；观察首次 AI 交互 |
| 第 2 周 | Day 8–14 | 引入跨专家/PersonalTrial；观察决策负担 |
| 第 3 周 | Day 15–21 | 观察提醒疲劳、缓存/加载、历史可读性 |
| 第 4 周 | Day 22–28 | 复盘、导出、退出访谈；数据核对 |
| 收尾 | Day 28–30 | 数据审计、匿名化、报告 |

最短 2 周只能回答“是否可用”，不能回答“长期恢复”；建议 4 周，至少 3 人完成。

## 2. 观察指标与证据

### 2.1 记录可靠性（客观日志 + 用户日记）

| 指标 | 采集 | 通过标准（建议） |
|---|---|---|
| 保存成功率 | 服务端 checkin/meal/recovery 记录数 vs 用户日记 | ≥98%，无静默丢失 |
| 重复保存 | 同 `submission_id`/同内容指纹计数 | 0 条重复入库 |
| 日期错位 | `session_meta.local_date` vs 用户日记/时区 | 0 条跨日错位 |
| 统计一致性 | 同一天用 `/period-summary`、`/training-calendar`、`/long-term-report`、`/training-facts` 交叉核对 | 同一口径数值一致；差异有解释 |
| 离线恢复 | 断网保存→恢复→刷新/重开 | 记录最终入库，失败记录可导出 |
| 媒体缺失 | 上传/分析/历史 | 失败有明确原因，不伪造结果 |
| 纠错 | 修改历史→统计/洞察/尝试 | 修订链与失效提示正确 |

> 注意：RC-0 已发现长期报告多动作低报、周期统计日期窗口不一致、尝试观察截断 8 次。试用前必须修复，否则会把已知缺陷记录成“用户问题”。

### 2.2 AI 有帮助性（问卷 + 访谈 + 输出抽样）

- 能否用自己的话解释“为什么给这个建议”（引用事实/适用条件）；
- 建议是否与当前目标、器械、伤病限制相关；
- 是否出现无关建议、重复提醒、过度推送；
- 遇到数据不足时是否说“不知道”，而不是编造；
- 是否把“一般信息”说成“诊断/处方”；
- 用户是否感到被替做决定（1–5 分）；
- 每周抽样 3 条 AI 输出，按 RC-1 的 factual/applicability/safety/agency 分类记录。

### 2.3 跨专家价值（任务后问卷 + 观察）

- 多专家意见是否帮助理解取舍，而不是增加负担；
- 能否复述双方立场与缺失信息；
- 是否出现“听 X 的”式选边；
- 用户最终是否自己做出决定（ignore/observe/propose/本次采用）；
- 决策时间、是否需要再次询问。

### 2.4 PersonalTrial 可用性

- 能否从一次训练建议开始尝试；
- 观察期是否能看到真实记录与达成情况；
- 复盘是否区分“已观察/可能解释/无法确认”；
- keep/adjust/stop/observe 是否可理解；
- 尝试结束后是否错误地自动改计划（应为 0）；
- 观察/复盘是否与真实记录一致（重点复核 RC0-08）。

### 2.5 移动端便利性

- 单组记录点击数、耗时（目标：≤3 次点击/组，正常网络 ≤5 秒）；
- 组间休息计时是否可一眼看清；
- 切后台/锁屏/来电后是否恢复；
- 单手操作、软键盘遮挡、误触；
- 营养搜索/份量输入步骤数；
- 视频上传/分析等待的可接受度。

### 2.6 长期恢复

- 4 周后冷启动时间、首屏可交互时间；
- IndexedDB/localStorage 体积、Service Worker 缓存大小；
- 历史记录（>100 条）滚动/筛选/详情是否可用；
- 低存储/低电量模式下的失败提示；
- 升级/刷新后旧数据是否可读；
- 崩溃/重启后的草稿与队列恢复。

## 3. 数据管理与伦理

- 仅收集必要数据；视频/症状为可选，默认最小化；
- 受试者 ID 与联系方式分离；报告只呈现匿名化汇总；
- 试用数据不进入模型训练/微调；不用于对外宣传；
- 退出即停止收集；试用结束后按同意书删除或匿名化；
- 任何严重不良事件（红旗症状、摔倒、伤情加重）立即停止相关训练并建议就医，记录时间线；不把责任推给用户；
- 试用不是临床试验，不宣称疗效/安全性结论。

## 5. 通过 RC-4 的最低证据（建议）

1. ≥5 名受试者、≥3 人完成 4 周；至少 1 名 iOS、1 名 Android（与 RC-2 设备矩阵一致）；
2. 记录丢失/重复/日期错位 = 0；统计交叉核对无未解释差异；
3. 严重安全事件 0；所有 AI 输出抽样无“诊断/处方/解除限制/替用户决定”严重错误；
4. PersonalTrial 至少 5 次完整闭环（开始→观察→复盘→决定），无自动改计划；
5. 移动端单组记录中位数 ≤3 次点击、≤5 秒（正常网络）；
6. 4 周后历史仍可读、缓存/存储无异常膨胀；
7. 退出/删除/导出可用；数据保留政策有记录。
