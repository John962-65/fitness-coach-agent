# M6.2（第一阶段）— 动作教学内容管线与关联

日期：2026-10-25 · 前置：M6.1.1（`a9a66a4`）复查通过。
本阶段按复查建议采用**内容数据与前端展示分离**：不新增页面，统一教学结构交给现有动作详情页渲染。

## 一、做了什么

### 1. 教学内容管线（后端）

- `coach/exercise_service.py` 新增 `teaching_for(ex_id)`：解析 `exercises/*.yaml` 的
  `knowledge_refs` → 读取 `knowledge/` 下对应的人工整理教学 md，
  拆 frontmatter（topic / source / provenance / updated）与正文。
- **路径安全**：ref 必须解析到 `knowledge/` 目录内且以 `.md` 结尾；
  目录穿越 / 非 md / 文件缺失一律跳过——宁可没有内容也不给错内容。
- `GET /exercises/{ex_id}` 响应新增 `teaching: [{path, topic, source[], provenance, updated, markdown}]`。

### 2. 已有关联（覆盖 18 个动作，零新造内容）

把仓库中**已整理好但未关联**的知识文件准确链接到匹配动作（14 个 yaml 各改 1 行）：

| 知识文件 | 新关联动作 |
| --- | --- |
| `chest/incline_chest.md` | 杠铃上斜卧推 |
| `shoulder/lateral_raise.md` / `db_shoulder_press.md` / `rear_delt_pumpkin.md` | 侧平举 / 哑铃推举 / 哑铃俯身飞鸟 + 面拉 |
| `back/rowing_variations.md` / `lat_activation.md` / `lat_pulldown_technique.md` | 杠铃划船 / 坐姿划船 / T杠划船 / 哑铃划船 / 引体向上 / 高位下拉 |
| `bicep_curl.md` / `tricep_training.md` | 杠铃弯举 / 锤式弯举 / 绳索下压 |

加上原有 4 个（深蹲/卧推/硬拉/RDL），**18 个核心动作具备"来源可追溯"的完整教学文档**。
所有内容来自项目既有的谭成义教学整理（`knowledge/20_exercises/`，frontmatter 标注来源与整理日期），
本轮只做关联，未新造任何教学内容。

### 3. 安全 Markdown 渲染器（前端，P1）

- 新增 `components/Markdown.tsx`：解析（`parseBlocks`/`parseInline` 纯函数，8 个 vitest 用例）
  与渲染分离；标题/引用/有序无序列表/**表格**/加粗/行内代码/分割线；全部经 React 元素输出，
  **无 dangerouslySetInnerHTML**。
- 接入两处：动作详情"教学"标签（教学文档渲染 + 来源标签 +
  "不构成医学建议；入库≠科学验证"注脚）；**AI 教练气泡**（真实回复的加粗/列表/表格正常显示，
  不再暴露 `**` 源码——实测截图 `m62-coach-markdown-390.png`）。
- 渲染细节：`|` 行只有在下一行是分隔行时才视为表格，否则并入段落（避免解析死循环，已回归测试）。

### 4. 封面缓存订阅刷新（复查遗留小项）

`invalidateExerciseCover()` 现在带版本号广播：挂载中的 `ExerciseCover` 订阅失效事件后立即重新查询，
同一页面完成媒体关联后占位图即时更新，无需重新进入页面。

### 5. 仓库级完整性测试

`test_all_knowledge_refs_in_repo_resolve`：每个 yaml 的 `knowledge_refs` 必须真实可解析
（含子目录）——错链会让教学内容静默消失，此测试显式拦截
（开发过程中它实际捕获了一次子目录前缀丢失的错误）。

- **未新造内容**：18 个动作的教学全部来自仓库既有整理文件；其余 52 个动作保持
  "教学指导尚未完善"的如实状态。扩到首批 20+ 需要新的来源整理（人工/资料），不能由 AI 直接生成后当作已验证知识。
