## 2. 发布模式：为什么只能是本地单用户

### 2.1 本地单用户模式（当前唯一可评估）

- 默认 `API_HOST=127.0.0.1`；绑定非回环地址且未设置 `API_ACCESS_TOKEN` 时启动直接拒绝（`backend/__main__.py`）。
- 配置令牌后，除 `/api/health` 与只读媒体/资产外，所有 `/api` 请求要求 `X-Access-Token`；`test_p7b.py::test_access_token_boundary` 通过。
- 跨用户读取矩阵（训练/事实/候选/统计/洞察/任务/尝试/限制/症状）通过；按 ID 触达返回 404/422。
- **但**：本地模式的“用户”由客户端声明 uid，媒体/资产使用共享令牌，不做逐资源归属；这不是多用户隔离。UI 导出不完整、无删除账户入口（RC0-17），账户删除不清媒体/缓存（RC0-16）。因此本地单用户也不满足 RC-0。

### 2.2 云端多用户模式（未实现，禁止使用）

`docs/p7b-identity-and-access.md` §3 只有设计：注册/登录、JWT/refresh 撤销、中间件按令牌覆盖路径 uid、逐资源授权、限流、审计、删除回收。代码中没有这些实现；当前 `uid` 仍来自路径/客户端声明，令牌是单一共享令牌。**不能把设计文档当作身份认证与授权已完成。** 公开部署会直接暴露跨用户读写/媒体访问风险，故云端模式在本次决策中为 **不可用**。

## 3. 阻断项清单（按优先级）

### 3.1 数据准确性与用户数据自主（RC-0 P1）

1. **RC0-10 备份恢复不完整/不幂等**：重复导入造成计划/身体/症状/限制重复；个人尝试、模板、食谱、器械、地点丢失；专业限制被写成 `lifted`；新用户恢复后无生效计划。
2. **RC0-16 账户删除范围不完整**：媒体文件、知识分块、任务事件、日志、客户端缓存未删除；无备份保留政策。
3. **RC0-17 导出/删除 UI 不完整**：前端只导出 profile/approach/trials，未调用后端完整导出；无删除入口。
4. **RC0-01 长期报告多动作低报**：8 组/4400kg 被报告为 4 组/2400kg。
5. **RC0-03 洞察过期**：新增训练后 next-training/协作洞察仍为 ready。
6. **RC0-08 个人尝试观察**：只取最近 8 次，结束后仍随新训练变化。

### 3.2 专业安全（RC-3）

7. **RC3-H1–H8 未获合格专业人员审核**：红旗分流、限制解除、疼痛前提动作、39 张涉及疼痛/伤病的卡、孕期/糖尿病/用药营养、视频→康复归因、复训计划、补剂/极端减脂。
8. 当前没有“已审核（合格专业人员）”的内容面；产品负责人签核、内部 YAML 校验、AI 整理都不等于专业审核。

### 3.3 实体设备与长期使用（RC-2/RC-4）

9. **T5 未执行**：没有 Android Chrome / iOS Safari/PWA 实体机记录；锁屏/后台、摄像头、MediaPipe、3D、PWA 安装、存储配额均未验证。
10. **T6 未执行**：没有 2–4 周真实使用、知情同意、数据审计；记录可靠性、AI 帮助性、跨专家价值、PersonalTrial 可用性、移动端负担、长期恢复均无证据。

### 3.4 T4 的已关闭问题与剩余边界

11. **已关闭（RC-1 修复并重跑）**：用户坚持危险目标时不再列出“风险自负”选项；聊天 system prompt 纳入 active TrainingRestriction；胸痛口语（“胸口有点痛”等）进入确定性红旗；用户拒绝提案会关闭；字符串字段不再被解析器丢弃。修复前 5 个严重安全错误在修复后 67 例 + 6 agent 探针中未复现。
12. **剩余边界**：RC-1 只证明这 67 个固定案例 + 6 个 agent 探针在该模型/版本/提示下没有已知可复现的严重安全错误；不能证明临床安全、所有输入安全；仍有 1 条未知 citation（collab-tr-02）待修。样本量、模型版本、温度、语言/文化覆盖均有限；详细局限见 RC-1 文档。

## 5. 什么情况下可以改变结论

### 5.1 从 BLOCKED → CONDITIONAL

必须同时满足：

- RC-0 的 6 项未修复 P1 全部修复并有回归/复现证据；P2 中与安全/隐私相关的项（导入安全字段、裸“好”确认、日期窗口）关闭；
- RC-1 的 1 条未知 citation（collab-tr-02）与 2 条轻微适用性（train-03 的 62.5kg 试探、rehab-03 的 urgent 标签）修复并重跑；
- RC-3 至少完成康复/运动医学与营养两个领域的独立专业审核，高风险内容有“已审核/待审核/不通过/不适用”记录；
- 明确限制功能范围（例如：仅本地单用户、仅低风险训练记录、不提供康复/医学营养建议、不宣称平台支持），并在 UI/发布材料中如实展示。

### 5.2 从 BLOCKED → PASS

在 5.1 基础上，还必须：

- RC-2 完成至少 Android Chrome + iOS Safari/PWA 实体机验收，记录设备/OS/浏览器/观察；
- RC-4 完成 ≥5 名受试者、≥3 人 4 周的真实试用，记录可靠性/帮助性/负担/长期恢复；
- RC-1 的严重安全错误为 0，且所有发现的问题已修复并重新评估；保留样本量与覆盖局限。

**当前没有任何一项达到 5.1，因此不能给 CONDITIONAL。**

## 6. 明确不宣称的事项

- 不宣称“临床安全”“专业认可”“经运动医学/营养/康复专业审核”；
